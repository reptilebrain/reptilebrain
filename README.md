# Hi, I'm P-A

I build small tools for Linux and Windows, usually to solve annoyances in my own workflow.

I prefer software that is predictable, cautious and easy to understand. That usually means dry-run support where it makes sense, validation before changes, isolated tests, CI and as few dependencies as practical.

## Projects

### [flymount](https://github.com/reptilebrain/flymount)

A Bash tool for managing SSHFS mounts on Linux with strict validation, plan-first behaviour and cautious defaults.

### [mariadb-tool](https://github.com/reptilebrain/mariadb-tool)

A Go utility for provisioning and managing MariaDB resources with a focus on repeatability, validation and safe reconciliation.

### [desktop-cleanup](https://github.com/reptilebrain/desktop-cleanup)

PowerShell scripts for keeping a Windows desktop tidy by moving files to predictable destinations without silently overwriting anything.

### [obsidian-inbox-import](https://github.com/reptilebrain/obsidian-inbox-import)

A small PowerShell tool that moves text files into an Obsidian inbox while deliberately leaving organisation to Obsidian and the user.

## General approach

- Small tools that do one thing
- Cautious defaults
- Dry-run or plan-first workflows where useful
- Fail rather than guess
- Automated tests and CI
- Clear documentation
- Minimal dependencies

Most of these tools started because I wanted something simple to behave in a very specific and predictable way.

Apparently that is how repositories happen.
